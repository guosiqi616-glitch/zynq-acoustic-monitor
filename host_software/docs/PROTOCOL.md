## 1. 范围与非目标

### 1.1 范围

本协议定义 Zynq-7010 设备到 PC 上位机的**单向**数据链路，承载四类信息：

- **设备信息与能力声明**（I 帧）
- **周期遥测**：双频带能量、BER、温湿度、状态、计数（T 帧）
- **硬件锁存事件**：锁存瞬间的特征快照与硬件时间戳（E 帧）
- **同步与健康状态**：时钟参考、标志位、错误与溢出计数（S 帧）

### 1.2 非目标（v1 不做）

- 上位机 → 设备的控制命令（调阈值、清计数、重启）：留给 v2
- 原始音频传输：音频不出 PL
- 多设备寻址、总线仲裁：v1 假定点对点
- 加密、鉴权、固件升级
- 报警音频、继电器等执行器控制

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 帧 | 一行以 CRLF 结尾的 ASCII 文本 |
| 遥测 | 周期性上报的运行数据 |
| 锁存 | PL 在阈值穿越的时钟沿把时间戳与特征值写入寄存器 |
| 窗口 | 能量积分的样本数，v1 为 512 |
| θ_warn | 预警阈值，只影响 `state` |
| θ_trig | 触发阈值，产生 `det`、`lock` 与 E 帧 |
| BER | 频带能量比，`E_high / (E_low + E_high)` |
| dBFS | 相对满量程的分贝值，0 为满量程 |

## 2. 传输层

### 2.1 UART（v1 默认）

| 参数 | 值 |
|---|---|
| 波特率 | 115200（协议不依赖波特率；需提速时两端一起改） |
| 数据位 | 8 |
| 校验 | 无 |
| 停止位 | 1 |
| 流控 | 无 |
| 物理层 | 3.3 V TTL，经 USB-UART 到 PC |

### 2.2 UDP（v1.1 预留）

- 一个数据报承载一帧，不拆包、不合并
- 默认端口 9000
- 帧格式与 UART 完全一致，解析器复用
- 丢包由 `seq` 检测，不做重传

### 2.3 带宽预算

| 帧 | 典型长度 | 频率 | 带宽 |
|---|---|---|---|
| T | 48–60 B | 50 Hz | ≈ 2.6 KB/s |
| I | 45–60 B | 1 Hz | ≈ 0.06 KB/s |
| S | 35–45 B | 1 Hz | ≈ 0.04 KB/s |
| E | 60–75 B | 事件驱动 | 可忽略 |

合计约 2.7 KB/s。115200 的 UART 有效带宽约 11.5 KB/s，余量约 4 倍——
这是帧率从 20 Hz 提到 50 Hz 后必须确认的一条：再往上提帧率就得同时提波特率。

## 3. 通用帧规则

| 编号 | 规则 |
|---|---|
| R1 | 编码为 ASCII 可打印字符 0x20–0x7E；出现其他字节，整行丢弃 |
| R2 | 一行一帧，以 `\r\n` 结尾；解析器同时容忍 `\n` |
| R3 | 字段用 `,` 分隔；字段内不得出现逗号 |
| R4 | 首字段为帧类型，单个大写字母：`I` `T` `E` `S` |
| R5 | 空行忽略；以 `#` 开头的行是注释，忽略 |
| R6 | 单帧正文最大 256 字节（不含 CRLF）；超长整行丢弃 |
| R7 | 数值为十进制整数：可带负号，允许前导零；禁止 `+`、空格、小数点、指数、`0x` |
| R8 | 字段数“至少”满足定义；多余尾字段忽略并给出告警（为 MINOR 升级留余地） |
| R9 | 未知帧类型：丢弃并计数，不得中断解析 |
| R10 | 禁止浮点文本；所有小数以整数缩放传输 |
| R11 | 禁止墙上时间；时间一律用设备上电后的单调微秒 |
| R12 | 字段顺序是线缆契约的一部分；调整顺序必须升 MAJOR |

## 4. 帧定义

### 4.0 时序

```
设备上电
  │
  ├── I ─────────────────────────────► 立即 1 次，之后 1 Hz
  ├── T ─────────────────────────────► 每 50 ms（20 Hz）
  ├── E ─────────────────────────────► 锁存瞬间立即发送
  └── S ─────────────────────────────► 每 1 s

上位机（v1）：只收不发
```

### 4.1 I 帧 — 设备信息

```
I,<major>,<minor>,<dev_id>,<fw>,<fs_hz>,<win>,<bands>,<caps>
```

参数 8 个，总 token 9 个。

| # | 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|---|
| 1 | major | u16 | ≥ 1 | 协议主版本，不兼容变更时 +1 |
| 2 | minor | u16 | ≥ 0 | 协议次版本，兼容新增时 +1 |
| 3 | dev_id | str[1..16] | `[A-Za-z0-9._-]` | 设备标识 |
| 4 | fw | str[1..16] | `[A-Za-z0-9._-]` | 固件版本 |
| 5 | fs_hz | u32 | 48000 | 采样率 |
| 6 | win | u16 | 512 | 能量窗口样本数 |
| 7 | bands | u8 | 2 | 频带数，v1 必须为 2 |
| 8 | caps | u16 | 位掩码 | 能力声明，见附录 B |

示例：

```
I,1,0,ZYNQ7010,0.3.1,48000,512,2,3
```

说明：

- 设备上电后**先发 I，再发第一条 T**，确保上位机先拿到版本与量纲。
- I 帧每 1 s 重发一次，上位机以最新一条为准。
- `bands != 2` 时上位机应给出“不支持的配置”告警，但仍按 2 带解析 T 帧。

### 4.2 T 帧 — 周期遥测（20 Hz）

```
T,<seq>,<t_us>,<temp>,<hum>,<db_low>,<db_high>,<ber>,<state>,<lock>,<det>,<supp>
```

参数 11 个，总 token 12 个。

| # | 字段 | 类型 | 单位/缩放 | 取值范围 | 无效值 | 说明 |
|---|---|---|---|---|---|---|
| 1 | seq | u32 | — | 0 .. 4294967295 | — | T 帧序号，回绕 |
| 2 | t_us | u64 | µs（上电起） | 0 .. 2^63−1 | — | 单调不减 |
| 3 | temp | i32 | °C × 100 | −4000 .. 12500 | −32768 | 温度 |
| 4 | hum | u32 | %RH × 100 | 0 .. 10000 | 65535 | 湿度 |
| 5 | db_low | i32 | dBFS × 10 | −1200 .. 0 | −32768 | 低频带能量 |
| 6 | db_high | i32 | dBFS × 10 | −1200 .. 0 | −32768 | 高频带能量 |
| 7 | ber | u16 | × 1000 | 0 .. 1000 | 65535 | `E_high/(E_low+E_high)` |
| 8 | state | u8 | 枚举 | 0 / 1 / 2 | 255 | 0 正常，1 预警，2 报警 |
| 9 | lock | u32 | 次 | 0 .. 4294967295 | — | 累计锁存次数 |
| 10 | det | u32 | 次 | 0 .. 4294967295 | — | 累计触发阈值穿越次数 |
| 11 | supp | u32 | 次 | 0 .. 4294967295 | — | 被不应期抑制的次数 |

示例：

```
T,1024,123456789,2537,5012,-812,-643,523,1,8,9,1
```

说明：

- `db_low`、`db_high` 是**同一窗口**内两个带通支路的能量，换算成 dBFS 后乘 10。
- `ber` 与 `db_*` 必须来自同一窗口，保证快照自洽。
- `det` 只统计**触发阈值**的上升穿越；预警阈值的穿越不计入。
- 传感器无效时使用哨兵值，不得用 0 代替（0 °C 是合法温度）。

### 4.3 E 帧 — 硬件锁存事件（立即发送）

```
E,<seq>,<t_us>,<db_low>,<db_high>,<ber>,<thr>,<lock>,<reason>
```

参数 8 个，总 token 9 个。

| # | 字段 | 类型 | 单位/缩放 | 取值范围 | 无效值 | 说明 |
|---|---|---|---|---|---|---|
| 1 | seq | u32 | — | 0 .. 4294967295 | — | E 帧独立序号 |
| 2 | t_us | u64 | µs（上电起） | 0 .. 2^63−1 | — | **锁存时刻** |
| 3 | db_low | i32 | dBFS × 10 | −1200 .. 0 | −32768 | 锁存瞬间低频能量 |
| 4 | db_high | i32 | dBFS × 10 | −1200 .. 0 | −32768 | 锁存瞬间高频能量 |
| 5 | ber | u16 | × 1000 | 0 .. 1000 | 65535 | 锁存瞬间 BER |
| 6 | thr | u16 | × 1000 | 0 .. 1000 | 65535 | 实际触发阈值 |
| 7 | lock | u32 | 次 | 1 .. 4294967295 | — | 这是第几次锁存 |
| 8 | reason | u8 | 枚举 | 0 / 1 / 2 | 255 | 0 阈值，1 手动，2 自检 |

示例：

```
E,15,123456800,-790,-610,564,550,8,0
```

说明：

- E 帧的 `t_us` 必须是 **PL 在锁存时钟沿写入的时间戳**，不是 PS 收到中断的时刻。
- E 帧允许早于对应的 T 帧到达；上位机收到即处理，不要等下一个 T。
- E 帧的 `lock` 应等于“上一条同 session 的 lock + 1”；跳号说明事件帧丢失。
- `reason=1`（手动）在 v1 中不会出现，预留给调试与自检。

### 4.4 S 帧 — 同步与健康（1 Hz）

```
S,<seq>,<t_us>,<flags>,<err_cnt>,<ovf_cnt>
```

参数 5 个，总 token 6 个。

| # | 字段 | 类型 | 取值范围 | 说明 |
|---|---|---|---|---|
| 1 | seq | u32 | 0 .. 4294967295 | S 帧序号 |
| 2 | t_us | u64 | 0 .. 2^63−1 | 当前设备时间，用于估时钟偏移 |
| 3 | flags | u16 | 0 .. 65535 | 位标志，见附录 C |
| 4 | err_cnt | u32 | 0 .. 4294967295 | 累计 I2C/传感器错误 |
| 5 | ovf_cnt | u32 | 0 .. 4294967295 | 累计事件 FIFO 溢出 |

示例：

```
S,60,123457000,3,0,0
```

说明：

- `ovf_cnt > 0` 表示有锁存事件因 FIFO 满而丢失，上位机必须标红。
- `flags` 是状态快照，不是累计值；`err_cnt` 与 `ovf_cnt` 是累计值。

### 4.5 字段设计六问

新增或修改字段时，逐条回答，答不上来就不要冻结：

1. 谁产生它？（PL 寄存器 / PS 计算 / 传感器）
2. 每帧都有吗？没有时填什么？
3. 单位是什么？缩放多少？
4. 物理范围是多少？越界怎么处理？
5. 无效值怎么表示？
6. 消费方拿不到时显示什么？

## 5. 时间语义

1. `t_us` 是设备上电后的微秒数，来源于 PL 的 100 MHz 自由运行计数器，原始分辨率 10 ns，传输时截断到 1 µs。
2. `t_us` 在单次上电内单调不减；重启后从 0 重新开始。
3. E 帧的 `t_us` 是“锁存那一刻”的硬件时间，由 PL 在时钟沿写入；PS 只做 `ticks/100` 换算，**不得**用收到中断的时刻重新打戳。
4. 若 `caps` 的 bit0 为 0，表示 `t_us` 来自 PS 软件计时（`XTime_GetTime`），精度较低；上位机应显示“软件时间戳”提示。
5. PC 侧另记 `t_pc_rx`（单调时钟），用于估算链路延迟：

```
offset       = min(t_pc_rx - t_us)      # 最近 10 s 窗口
latch_to_pc  = t_pc_rx - (t_us + offset)
```

6. 协议中不出现墙上时间（年月日时分秒），避免时区、对时、夏令时问题。

## 6. 计数、状态与不变量

### 6.1 阈值与状态

```
state = 2   if ber >= θ_trig
state = 1   if ber >= θ_warn
state = 0   otherwise
```

- `θ_warn` 只影响 `state` 的显示，不产生事件、不计入 `det`。
- `θ_trig` 产生 `det`、`lock` 与 E 帧，并在 E 帧的 `thr` 中回传。
- 阈值属于设备配置，不在协议中固定；上位机以 E 帧的 `thr` 为准显示。

### 6.2 不变量

| 编号 | 不变量 | 违反时的含义 |
|---|---|---|
| I1 | `det = lock + supp`（按 32 位无符号回绕比较） | 设备计数逻辑错误，或 T 帧被篡改 |
| I2 | `ber = round(1000 × E_high / (E_low + E_high))` | 设备换算错误 |
| I3 | `lock`、`det`、`supp` 在单次上电内单调不减 | 计数器回绕或重启未识别 |
| I4 | `t_us` 在单次上电内单调不减 | 时间戳来源错误 |
| I5 | `ovf_cnt = 0` | 事件 FIFO 溢出，存在漏检 |
| I6 | 同一 session 内，收到的 E 帧数 = 最后一次 T 的 `lock` | 事件帧丢失 |
| I7 | E 帧的 `lock` 连续递增，步长为 1 | 事件丢失或重复 |

> I1 与 I6 是“零漏检”的自动证明：上位机不需要相信宣传，直接看这两个等式。
> I6 的前提是“从 session 起始开始统计”（起始 `lock` 为 0）；若从上电中途接入，应按 `lock` 的增量计算。

### 6.3 session（会话）

一次上电周期称为一个 session。以下任一情况判定为新 session：

- 收到新的 I 帧，且距上一条 I 超过 2 s；
- `t_us` 比上一条记录倒退超过 1 s；
- `lock`、`det`、`supp` 同时归零。

新 session 开始时，上位机必须：

- 重置 `seq` 跟踪与丢帧计数；
- 重置 E 帧计数；
- 保留历史 session 的记录，但不在 UI 上把重启算成丢帧。

## 7. 错误处理

### 7.1 解析器原则

- 任何非法输入都不得抛异常、不得退出、不得清空已有状态。
- 丢弃当前行，错误计数 +1，继续读下一行。
- 行是自定界的，不需要字节级重同步。
- 单行处理时间必须是常数级，不随输入长度增长（行长已限制 256）。

### 7.2 校验级别

v1 采用**单级校验**：结构、语法、范围任一不合法，整行丢弃。

- 无效传感器数据只能用哨兵值表达，不能用越界值表达。
- 上位机可对显示值做钳位，但不得把钳位后的值写回协议层。

### 7.3 错误码

| 错误码 | 触发条件 | 处理 |
|---|---|---|
| `E_TOO_LONG` | 行长 > 256 字节 | 丢行 |
| `E_BAD_ASCII` | 含非 0x20–0x7E 字节 | 丢行 |
| `E_UNKNOWN_FRAME` | 首字段不是 I/T/E/S | 丢行并计数 |
| `E_FIELD_COUNT` | 字段数少于定义 | 丢行 |
| `E_BAD_INT` | 不是合法十进制整数 | 丢行 |
| `E_RANGE` | 数值越界且不是哨兵 | 丢行 |
| `E_BAD_TOKEN` | `dev_id`/`fw` 不合规 | 丢行 |
| `E_EXTRA_FIELDS` | 字段数多于定义（告警） | 保留，忽略多余字段 |
| `E_UNSUPPORTED_BANDS` | `bands != 2`（告警） | 保留，按 2 带解析 |

### 7.4 断线与重启

| 现象 | 判定 | UI 行为 |
|---|---|---|
| 500 ms 无 T | 延迟 | 数值变灰，显示“延迟” |
| 2 s 无 T | 丢失 | 显示“信号丢失”，保留最后值 |
| 5 s 无 T | 断开 | 显示“重连中”，停止动画 |
| `t_us` 倒退 > 1 s | 重启 | 新建 session，弹提示 |
| 收到新 I 且间隔 > 2 s | 重连 | 重新协商版本 |

### 7.5 速率约束

| 帧 | 标称 | 允许范围 | 超限处理 |
|---|---|---|---|
| T | 20 Hz | 5–60 Hz | 告警，不丢帧 |
| I | 1 Hz | 0.2–2 Hz | 告警 |
| S | 1 Hz | 0.2–2 Hz | 告警 |
| E | 事件驱动 | ≤ 20 Hz（不应期 50 ms） | 超限告警“抖动” |

## 8. 版本规则

### 8.1 编号

- 格式 `MAJOR.MINOR`。
- MAJOR：不兼容变更。
- MINOR：向后兼容的新增。
- 文档笔误、注释修正：不改线缆版本，只记变更记录。

### 8.2 什么算 MAJOR

- 删除、重命名、重排字段；
- 修改单位或缩放（如 °C×100 → °C×1000）；
- 修改帧类型字母或字段语义；
- 修改不变量；
- 修改 `state`/`reason` 的既有含义。

### 8.3 什么算 MINOR

- 新增帧类型（老解析器按 R9 忽略）；
- 在帧尾追加字段（老解析器按 R8 忽略）；
- 新增 `caps` 位；
- 新增枚举值（消费方必须容忍未知值）；
- 新增哨兵值（不得与现有合法值冲突）。

### 8.4 协商流程

1. 设备上电先发 I，之后每 1 s 一次。
2. 上位机 3 s 内未收到 I：提示“未识别到设备”，继续显示原始日志。
3. `major` 不匹配：红色横幅“协议不兼容”，停止解析业务帧，保留原始日志。
4. `minor` 大于上位机支持：黄色提示“固件较新，部分字段可能未识别”，继续解析。
5. v1 是单向链路，上位机不回发任何数据。

### 8.5 兼容矩阵

| 固件 | 上位机 | 结果 |
|---|---|---|
| 1.0 | 1.0 | 正常 |
| 1.1 | 1.0 | 正常，忽略新增尾字段/新帧 |
| 1.0 | 1.1 | 正常，缺失字段用默认值 |
| 2.0 | 1.0 | 拒绝，提示升级上位机 |

### 8.6 冻结流程

1. 写字段表与示例；
2. 用参考解析器跑通全部测试向量；
3. 找一位未参与的人，只读本文写解析器；
4. 修订歧义；
5. 打 tag `proto-v1.0`，登记变更记录；
6. 冻结后任何修改走 8.1–8.3。

## 9. 示例

### 9.1 合法

```
I,1,0,ZYNQ7010,0.3.1,48000,512,2,3
T,1024,123456789,2537,5012,-812,-643,523,1,8,9,1
E,15,123456800,-790,-610,564,550,8,0
S,60,123457000,3,0,0
```

### 9.2 边界

## 10. 测试与一致性

### 10.1 测试向量

`protocol/vectors.json` 是 C 与 JS 共用的用例集：

```json
{
  "protocol": "1.0",
  "cases": [
    {"name": "t_normal", "line": "T,1024,...", "ok": true, "kind": "T",
     "fields": {"temp": 2537, "ber": 523, "lock": 8}}
  ]
}
```

要求：

- C 解析器与 JS 解析器跑**同一份**向量；
- 合法的用例校验解析结果，非法的用例校验错误码；
- 每次改动协议，先改向量，再改代码。

### 10.2 一致性脚本

`tools/conformance.py` 支持（在 `host_software/` 目录下执行）：

```bash
# 只跑测试向量
python tools/conformance.py --vectors protocol/vectors.json

# 连真实设备跑 60 秒
python tools/conformance.py --source serial:COM5@115200 --seconds 60

# 回放录制的日志
python tools/conformance.py --source file:records/session1.log
```

检查项：

| 检查项 | 判据 |
|---|---|
| 收到 I 帧 | 至少 1 条 |
| 协议版本 | major 匹配 |
| T 帧率 | 5–60 Hz（按 t_us 计算） |
| seq 连续性 | 无缺号（回绕除外） |
| t_us 单调 | 不倒流（重启除外） |
| `det = lock + supp` | 每条 T 都成立 |
| 计数单调 | 不倒退（重启除外） |
| `ovf_cnt` | 最终为 0 |
| E 帧完整性 | E 帧数 = 最终 lock |
| 解析错误 | 0（可用 `--allow-errors` 放宽） |

> 未知帧也会计入“解析错误”。若设备上电会打印非协议 banner，用 `--allow-errors 1` 放宽。

### 10.3 实现建议

- C 解析器放在不依赖 Xilinx 头文件的 `protocol.c/.h`，PC 上用 gcc 编译并跑向量；上板复用同一份源码。
- JS 解析器单独成文件，不依赖 DOM，便于在 Node 里跑向量。
- 两边都遵守“解析器永不抛异常”。

### B. `caps` 位定义

| 位 | 值 | 含义 |
|---|---|---|
| 0 | 1 | E 帧时间戳来自 PL 硬件计数器 |
| 1 | 2 | 存在事件 FIFO |
| 2 | 4 | 阈值可由上位机写入（v1 恒 0） |
| 3 | 8 | 支持 UDP 传输（v1 恒 0） |
| 4–15 | — | 保留，置 0 |

### C. `flags` 位定义（S 帧）

| 位 | 值 | 含义 |
|---|---|---|
| 0 | 1 | PL 就绪 |
| 1 | 2 | SHT30 正常 |
| 2 | 4 | 曾发生事件 FIFO 溢出 |
| 3 | 8 | 曾发生 UART 发送丢字节 |
| 4–15 | — | 保留，置 0 |

### D. 哨兵值

| 字段 | 哨兵 | 含义 |
|---|---|---|
| temp | −32768 | 传感器无效 |

| state / reason | 255 | 未知 |

### E. 与旧版字符串的映射

旧版（v0，已被本协议取代）：

```
Temp:25.3C,Humi:50.1%,BER:0.42,Status:ALARM
```

对应 v1.0 的 T 帧：

```
T,<seq>,<t_us>,2530,5010,<db_low>,<db_high>,420,2,<lock>,<det>,<supp>
```

差异：

- 旧版无 `seq`、无时间戳、无计数，无法检测丢帧与漏检；
- 旧版用浮点文本，裸机格式化开销大；
- 旧版只有单带能量，没有双带 dBFS 与锁存快照。

迁移时，PS 侧的组帧函数整体替换；上位机侧建议直接使用新的 Web 看板，旧的 PyQt 界面不再维护。

### F. C 实现清单（PS 裸机）

- [ ] `protocol.h` 定义 `PROTO_MAJOR`、`PROTO_MINOR`、帧字母、字段数、`MAX_LINE`。
- [ ] `proto_build_I()`、`proto_build_T()`、`proto_build_E()`、`proto_build_S()` 四个组帧函数。
- [ ] 64 位 `t_us` 用自写的 `u64_to_dec()` 格式化；不要依赖 `xil_printf` 的 `%llu`。
- [ ] 不使用 `%f`；所有小数已缩放为整数。
- [ ] 组帧缓冲 256 字节，检查 `snprintf` 返回值，截断即丢弃。
- [ ] 每种帧独立 `seq`，`uint32_t`，发送后自增。
- [ ] 上电先发 I，再发首条 T。
- [ ] E 帧在 ISR 里读取 PL 快照后立即组帧入队，主循环发送。
- [ ] UART 发送用环形缓冲 + TX FIFO 空中断，禁止阻塞式 `printf`。
- [ ] `t_us` 优先取 PL 计数器 `ticks / 100`；退化时用 `XTime_GetTime()` 并清 `caps` bit0。
