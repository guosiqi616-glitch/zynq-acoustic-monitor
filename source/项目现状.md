## 三、系统架构

```
ES8388 ──I2S(48k)──> PL                              PS (Cortex-A9)           PC
                     I2S 接收 + 两级 CDC              ┌────────────────┐
                     ↓                               │ 动态基线跟踪     │
                     双带 31 阶 FIR                  │ 多维卡方判决     │
                     (1–4k / 8–16k)                  │ 语音抑制         │
                     ↓                               │ 事件状态机       │
                     512 点滑动能量                   │ SHT30 温湿度     │
                     ↓                               │ 协议组帧 50 Hz   │
                     BER / 噪声底 → AXI GPIO ───────>│                │──UART──> Python 桥接 ──HTTP/WS──> 浏览器
                     双判据 + 硬件锁存 ──状态/计数──>│                │
                     └───────────────────────────────┴────────────────┘
```

**分工**：PL 负责连续音频的特征提取与硬件锁存；PS 负责动态基线、多维判决、环境采集与事件调度。

### 5.3 抗噪声对比实验（144 次试验）

2 种噪声（白 / 高频）× 3 档强度 × 4 类异响 × 6 次，四组判据在同一特征流上对比：

| 判据 | 纯噪声段告警占空比（6 种条件） | 结论 |
|---|---|---|
| 固定能量阈值 | 0% / **100%** / **100%** / 0% / **100%** / **100%** | 噪声一升就常亮失效 |
| 单侧固定 BER | 0% / 0% / 0% / **100%** / **100%** / **100%** | 高频噪声下失效；白噪声下仅 50% 检出 |
| 双侧固定 BER | 0% / 0% / 0% / **100%** / **100%** / **100%** | 同上 |
| **多维判决（本方案）** | **全部 0%** | 4/6 条件检出率 ≥ 95% |

## 七、已知限制与边界

| 项 | 说明 |
|---|---|
| **中断未做** | AXI GPIO 的 `C_INTERRUPT=0`，PS 靠 50 Hz 轮询；上报延迟 ≤20 ms |
| **峭度通道未接通** | PL 的 `status[31:28]` 实测恒为 0，时间结构维实际靠能量突增 |
| **单次冲击挡不住** | 关门、脚步与机械冲击在时域同构，仍会触发；语音能挡 |
| **音频回溯未做** | 串口带宽 115 kbps，原始音频 768 kbps，差 7 倍 |
| **QSPI 未固化** | 断电后必须重新烧写 |
| 音频输入 | 麦克风（经放大模块）与线路输入两路均可用；演示用线路输入以保证可重复 |
| **滤波器 31 阶** | 48 kHz 下过渡带约 5.6 kHz，两带重叠；改 127 阶几乎不花资源 |
| 语音判定的副作用 | 播语音时状态灯可能短暂闪红，但不弹窗、不记事件 |

## 十、答辩口径（关键三句）

1. **为什么用 Zynq**：一个样本只用了 32 个时钟，剩下 1009 个是空的；ARM 不碰样本，只做判决和调度。
2. **怎么抗噪声**：不比绝对音量，比"偏离自身基线多少"；六种噪声环境下固定阈值全部失效，动态基线占空比为 0。
3. **边界在哪**：语音能挡（BER 持续低于基线 440 ms），单次冲击挡不住——它和机械冲击在时域同构，需要包络周期性分析，是下一步。
