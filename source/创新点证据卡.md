# 四个创新点：证据卡

> 用途：答辩/申报书里每个创新点只用一页，标题 + 一句话结论 + 数字 + 出处。
> 原则：**没有数字的论断不写**；做不了的，写成"边界"而不是"创新"。

---

## 创新一：从软件轮询转向 FPGA 流水线并行处理

**一句话**：音频特征提取全部在 PL 完成，ARM 不接触样本，处理时间只占时间预算的 3%。

### 四个必须能报出来的数字

| 指标 | 数值 | 怎么来的 |
|---|---|---|
| 吞吐率 | **48 kHz 连续，无丢样** | 每样本 20.83 µs 到达，busy 握手保证不覆盖 |
| 单样本处理时间 | **0.64 µs** | 31 抽头 × 2 带，时分复用 2 个乘法器，32 拍 @ 50 MHz |
| 时间预算占用 | **3.1%** | 0.64 µs / 20.83 µs |
| 资源占用 | **LUT 10.5% / FF 8.0% / DSP 7.5% / BRAM 0** | Vivado 实现报告 |
| 时序 | **WNS > 0，全约束满足** | 50 MHz 时钟 |

> 答辩时这句话最有杀伤力：**"一个样本只用了 32 个时钟，剩下的 1009 个时钟是空的。"**
> 它同时说明了"为什么 MCU 做不到"和"还有多少余量做三带/127 阶"。

### 延迟必须拆开说（否则会被抓）

现在文档里写的"端到端延迟 3.2 ms"**没有说明测的是哪一段**，这是答辩风险点。建议按下面拆开报：

| 环节 | 延迟 | 依据 |
|---|---|---|
| 双带 FIR 群延迟 | **0.31 ms** | 31 抽头线性相位，(N−1)/2 = 15 样本 |
| 滑动能量特征更新 | **10.7 ms** | 512 点窗 / 48 kHz |
| PL 判决与确认 | **3 ms** | 1 kHz 节拍 × 3 帧确认 |
| PL 锁存 → PS 组帧 | **≤ 20 ms** | 50 Hz 轮询 |
| 串口帧传输 | **≈ 5.6 ms** | 65 字节 @ 115200 |

**结论**：PL 快路径（硬件锁存 → PC 显示）约 **23 ms**；PS 多维判决路径还需 120 ms 确认，合计约 **140 ms**。
把 3.2 ms 明确标注为"串口帧传输时延"或直接删掉，改报这两个数。

## 创新二：基于多频带能量比的抗环境噪声识别

**一句话**：固定阈值在 6 种背景噪声下有 2–3 种会"常亮失效"，动态基线在全部 6 种条件下误报占空比为 0。

### 已有数据（144 次试验，可复现）

| 判据 | 纯噪声段告警占空比 | 检出率 |
|---|---|---|
| 固定能量阈值 | 0% / **100%** / **100%** / 0% / **100%** / **100%** | 高，但失效后无意义 |
| 单侧固定 BER | 0% / 0% / 0% / **100%** / **100%** / **100%** | 白噪声下仅 50% |
| 双侧固定 BER | 0% / 0% / 0% / **100%** / **100%** / **100%** | 高，但高频噪声下失效 |
| **多维判决（本方案）** | **全部 0%** | 4/6 条件 ≥ 95% |

**答辩口径**："误报不是变少了，是从'判据恒为真'变成了'判据能自适应'。固定阈值在白噪声下可用、换成高频噪声就失效；我们把基线做成持续跟踪的，六种条件下都不误报。"

**边界要主动说**：`loud_hf`（高频强噪声 + 低信噪比）下检出率 37.5%。这是频带能量比方法的物理边界——背景本身占据高频带时，高频异响不再改变能量分布。改进方向是补时间结构维，不是继续调阈值。

## 创新三：基于硬件锁存与中断的异常事件捕获

**一句话（现在能说的）**：异常在 PL 侧硬件锁存，事件不依赖软件轮询发现，实测无丢失。

**一句话（现在不能说的）**：中断还没有做。**不要说"通过中断通知 PS"，会被现场翻代码。**

### 现状与数字

| 能力 | 状态 | 数字 |
|---|---|---|
| 硬件锁存 | ✅ | 3 ms 确认 / 40 ms 解除 |
| 事件计数 + 序号 | ✅ | 16 位计数，PS 侧融合为统一事件号 |
| 锁存 → 上报 | ✅（轮询） | ≤ 20 ms |
| **中断** | ❌ 未做 | 需改 BD + 重建 bitstream |
| 事件 FIFO | ❌ 未做 | — |
| 音频回溯 | ❌ 未做 | 串口带宽差 7 倍 |

**答辩口径**："当前是 50 Hz 轮询读取锁存状态，最坏 20 ms 上报；因为判定和锁存都在 PL 完成，轮询只影响'报得多快'，不影响'会不会漏'。中断通道已规划，可把上报压到 100 µs 以内，属于下一步优化。"

> 如果时间允许做中断，这段话可以升级成实测数字；做不了就照上面说，**主动交代边界的可信度高于模糊表述**。

## 创新四：多模态监测与轻量化 PC 上位机

**一句话**：不用外接显示屏，Windows 端一块页面同时看到能量、BER、动态基线、判决级别、温湿度和事件记录。

### 看板现在能看到什么

| 区域 | 内容 | 状态 |
|---|---|---|
| 频带能量比 | BER 大数字 + 阈值 + 本底 + 双带占比 | ✅ 原有 |
| 趋势 | BER 120 秒曲线 | ✅ 原有 |
| 事件 | 最近锁存、时间、能量比、历史列表 | ✅ 原有 |
| **多维判决（新增浮层）** | 级别 L0–L3、卡方判决分、基线 μ±σ、残差 BER、噪声底、命中的判据 | ✅ 今天新增 |
| 环境 | 温度、湿度 | ✅ 原有 |
| 温声关联 | 温度高于基线 3 ℃ 且声学异常 → 标记"过热关联" | ✅ 固件已实现，浮层显示 |

### 答辩口径

"多模态不是把温湿度摆在同一块屏幕上，而是它参与判决：温度是慢变量，几乎不会被噪声误触发，所以用它给声学异常做置信度加成——温度持续上升 + 高频异响，才判为'疑似轴承过热'。单纯的声音报警做不到这一点。"

> 注意：目前这条融合规则还没有独立的对照实验。可以说"已实现融合判据"，**不能说"提升了准确率"**。

---

## 一句话总览（答辩开场用）

> 我们把音频特征提取放进 PL，一个样本只用 32 个时钟；把判据从固定阈值改成持续跟踪的动态基线，六种噪声环境下误报占空比从 100% 降到 0；异常在硬件侧锁存，事件不丢；上位机不需要外接屏幕就能看到判决全过程。
