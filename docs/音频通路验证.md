# 音频输入验证手册

> 目的：确认「真实音频 → codec ADC → I2S → PL FIR → 能量 → AXI → PS → 串口」整条链路，
> 同时回归验证今天改过的所有东西（CDC、时序、频带能量比、诊断输出）。

---

## 一、准备

**硬件**

| 东西 | 说明 |
|---|---|
| 3.5mm 公对公音频线 | 手机/电脑耳机口 → 板子的音频输入座（LINE IN） |
| 耳机 | 插板子的 PHONE 口，用于 loopback 自检 |
| 音源 | 手机或电脑 |

**测试音频**（已生成，直接用播放器打开）

## 二、第 0 步：先验音频通路（耳机 loopback）

设计里 `aud_dacdat` 直接把 ADC 数据送回 DAC，所以这一步不需要看串口。

1. 耳机插到板子的 **PHONE / 绿色音频输出口**
2. 3.5mm 线接好输入，播放 `tone_1kHz.wav`

**判断：**

| 现象 | 结论 | 下一步 |
|---|---|---|
| 耳机里能听到 1 kHz 蜂鸣 | codec + I2S + 时钟全通 ✅ | 进入第 1 步 |
| 完全没声 | codec 那边的问题 | 先别往下做，见第六节 |

> 这一步能听到底噪说明 codec 在工作；完全没声先查 I2C 配置和 MCLK。

## 三、第 1 步：看串口原始能量

**顺序很重要：先开串口，再跑脚本**，否则看不到启动那几行。

1. 打开 **XCOM**，选 **COM6**，**115200**，8N1，点「打开串口」
2. 另开 cmd，运行：

```
D:\Xilinx\Vitis\2020.2\bin\xsct.bat D:\Xilinx\S\project\project_1\run_board.tcl
```

3. 串口里应该出现：

```
[INFO] SHT30 I2C ready at 0x44
[INFO] AXI GPIO audio energy at 0x41200000
[DIAG] TRI1=FFFFFFFF TRI2=FFFFFFFF (expect FFFFFFFF FFFFFFFF)
[INFO] first energy low=... high=... (hex ... ...)
[RAW] 0 ... ... R=...
```

**回归检查点 ①**：`TRI1` / `TRI2` 必须是 `FFFFFFFF`（说明 AXI GPIO 两路都配成了全输入）。

4. 播放 `tone_1kHz.wav`，盯住 `[RAW]` 行（只在前 5 秒打印，想再看就重跑脚本）

**预期：`low` 明显变大（从个位数跳到几万），`high` 基本不动，R 变小。**

5. 换 `tone_10kHz.wav` 重跑一次

**预期：反过来，`high` 变大，R 变大。**

## 四、第 2 步：用工具跑统计，留证据

每段场景录 10 秒，自动存 CSV 并打印统计。**录之前先关掉 XCOM**（串口只能被一个程序占用）。

```
cd /d D:\Xilinx\S\project\project_1
.venv\Scripts\python.exe tools\record_serial.py --port COM6 --seconds 10 --label silence
.venv\Scripts\python.exe tools\record_serial.py --port COM6 --seconds 10 --label 1kHz
.venv\Scripts\python.exe tools\record_serial.py --port COM6 --seconds 10 --label 10kHz
.venv\Scripts\python.exe tools\record_serial.py --port COM6 --seconds 10 --label sweep
```

每段之间切换音源，CSV 会存到 `records\verify_<标签>_<时间>.csv`。

### 4.1 详细操作（一次场景，约 2 分钟）

**① 关掉 XCOM**

串口同一时间只能被一个程序打开。点 XCOM 的「关闭串口」，再关窗口。

**② 确认板子还在跑**

板子不用重新烧，只要没断电、没按复位键，程序就一直在发帧。

**③ 开一个 cmd 窗口，进到工程目录**

```
cd /d D:\Xilinx\S\project\project_1
```

**④ 造出这个场景的声音**

- `silence`：什么都不放
- `1kHz` / `10kHz` / `sweep`：**双击 `test_audio\` 里对应的 WAV**，系统播放器会开始放。
  单频文件已经加长到 **30 秒**，比 10 秒采集窗口长得多，**不需要设循环**。
  播完自动停，或者手动暂停都行。

> 也可以直接用手机放音（手机装个信号发生器 App），效果一样。
> 注意：cmd 窗口只用来跑采集命令，不要在那个窗口里放音。

**⑤ 在步骤 ③ 那个 cmd 里执行**

```
.venv\Scripts\python.exe tools\record_serial.py --port COM6 --seconds 10 --label 1kHz
```

10 秒后自动结束，屏幕上会打印摘要，同时生成一个 CSV。

**⑥ 换场景**：改 `--label`，换音源，重复 ④⑤。

> 每个 CSV 名字都带时间戳，不会互相覆盖。
> 注意 `--label` 只是标签，随便写，但四个场景**建议统一用 `silence` / `1kHz` / `10kHz` / `sweep`**，后面好对照。

### 4.2 摘要怎么读

```
frames        : 201  (20.1 fps)          <- 帧率，必须 ~20
db_low        : min -520  max -410  mean  -470.3
db_high       : min -800  max -760  mean  -781.2
ratio(0-1000) : min   12  max   38  mean    24.5   <- 主要看这个
seq continuity: OK                       <- 必须 OK，有 gaps 说明丢帧
```

- `frames` 不是 20 左右 → 波特率错 / 串口选错 / 板子没在跑
- `seq continuity` 有 gaps → UART 丢帧，或者采集脚本被别的程序抢了串口
- `ratio` 的 `mean` 就是填表用的数

### 4.3 CSV 在哪、怎么看

```
D:\Xilinx\S\project\project_1\records\verify_1kHz_20261029_214012.csv
```

列：`label, seq, t_us, temp100, hum100, db_low, db_high, ratio, state, lock, det, supp`

双击用 Excel 打开即可。答辩时可以把四个场景的 ratio 画成柱状图。

---
**判据表**（实测值，2026-10-30，`tone_*.wav` 经 PC 声卡 → 板载 LINE IN，已加噪声门限）

| 场景 | `db_low` | `db_high` | `ratio` 均值 | `ratio` 最大 |
|---|---|---|---|---|
| silence | −946 | −909 | **0** | **0** |
| **1 kHz** | **−611** | −915 | **0** | 1 |
| **10 kHz** | −814 | **−537** | **955** | 999 |

**结论**：双带分离成立，`ratio` 随频率单调上升（1 kHz ≈ 0 → 10 kHz ≈ 955），
静音时被噪声门限压成 0，不再乱跳。RTL 音频处理链验收通过。

**回归检查点 ②**：`frames` 必须是 **20 帧/秒左右**，`seq continuity` 必须是 **OK**。

## 六、失败了怎么查（决策树）

```
播放 1 kHz，耳机有声但串口 low 一直是 0
  ├─ 耳机有声 → ADC 数据是好的，问题在 PL 采数
  │    → 大概率是 CDC 采样点不对（rx_rise 没落到数据稳定区）
  │    → 下一步：把 adc_data 直接接到能量输出，看能不能读到非零样本
  └─ 耳机没声 → codec 没工作
       → 查 I2C 配置是否成功（示波器看 aud_scl/aud_sda）
       → 查 MCLK 12.288 MHz 有没有出来（示波器看 aud_mclk）
```

```
播放 1 kHz，low 变大了但 R 还是很大（>600）
  → FIR 频带划分不对，或者播的不是 1 kHz
  → 先播 sweep，看 R 在整个频段怎么走
```

```
XCOM 打不开 COM6（拒绝访问）
  → 被别的程序占着：关掉另一个 XCOM、record_serial.py、我这边的抓包进程
  → 用任务管理器看有没有残留的 python.exe
```

```
run_board.tcl 报 No devices detected on target
  → Vivado Hardware Manager 或 Vitis debug 占着 hw_server
  → 关掉它们，任务管理器结束 hw_server.exe，重跑
```

## 七、这一轮要签字确认的清单

- [ ] 耳机 loopback 能听到 1 kHz
- [ ] `[DIAG] TRI1=FFFFFFFF TRI2=FFFFFFFF`
- [ ] 静音时 `[RAW]` 的 low/high 接近 0
- [ ] 1 kHz 时 low 明显上升，ratio < 300
- [ ] 10 kHz 时 high 明显上升，ratio > 600
- [ ] sweep 时 ratio 单调上升
- [ ] `record_serial.py` 报告 20 fps、序号连续
- [ ] `fast_probe.tcl` 显示数值成段稳定
- [ ] 时序报告 `All user specified timing constraints are met`
