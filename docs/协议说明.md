# 串口通信协议 v1.1

板子（PS 端）通过 UART 向上位机发送文本帧。协议刻意做得简单：**一行一帧，ASCII，逗号分隔**，用串口助手就能直接看，不需要任何解析工具。

---

## 物理层

| 项目 | 值 |
|---|---|
| 波特率 | 115200 |
| 数据位 / 校验 / 停止位 | 8 / 无 / 1 |
| 电平 | TTL（经 CH340 转 USB） |
| 编码 | 可打印 ASCII |
| 单行最大长度 | 256 字符 |

---

## 通用规则

1. 每行以**帧类型字母**开头，字段间用 `,` 分隔，以 `\r\n` 结束。
2. 空行与以 `#` 开头的行**直接忽略**（板子启动信息就是 `#` 开头的注释）。
3. 字段数少于规定值 → 整帧丢弃，记 `E_FIELD_COUNT`。
4. 字段数多于规定值 → 照常解析，但记 `E_EXTRA_FIELDS`（向前兼容）。
5. 未知帧类型 → `E_UNKNOWN_FRAME`，丢弃。
6. 数值字段必须为十进制整数，允许前导 `-`。

### 单位约定

| 量 | 单位 | 说明 |
|---|---|---|
| `t_us` | 微秒 | 板子上电后的单调时间戳 |
| `temp` | 0.01 ℃ | 2780 = 27.80 ℃ |
| `hum` | 0.01 %RH | 1990 = 19.90 %RH |
| `db_low` / `db_high` | 0.1 dB | 数值 = `10·log10(E) − 100`，因此 `-900` 表示 −90.0 dB |
| `ber` | 千分比 | 0–1000，753 表示 0.753 |
| `state` | 枚举 | 0 正常 / 1 关注 / 2 事件中 |

### 无效值（哨兵）

| 字段 | 哨兵值 | 含义 |
|---|---|---|
| `temp` | `-32768` | 传感器未读到 |
| `hum` | `65535` | 传感器未读到 |
| `db_low` / `db_high` | `-32768` | 能量为零（无输入） |
| `ber` | `65535` | 无有效值 |
| `state` | `255` | 未知 |
| `reason` | `255` | 未知 |

---

## 帧类型

| 帧 | 频率 | 字段数（不含帧头） | 用途 |
|---|---|---|---|
| `I` | 上电一次 + 1 Hz | 8 | 设备信息 |
| `T` | 50 Hz | 11 | 遥测主帧 |
| `E` | 事件触发 | 8 | 事件快照 |
| `S` | 1 Hz | 5 | 状态与错误计数 |
| `X` | 10 Hz | 15 | 诊断中间量（v1.1 新增） |

---

## I 帧 —— 设备信息

```
I,1,1,ZYNQ7010,0.2.0,48000,512,2,0
```

| # | 字段 | 类型 | 说明 |
|---|---|---|---|
| 1 | `major` | u16 | 协议主版本，当前 1 |
| 2 | `minor` | u16 | 协议次版本，当前 1 |
| 3 | `dev_id` | 字符串 | 设备标识，`[A-Za-z0-9._-]{1,16}` |
| 4 | `fw` | 字符串 | 固件版本 |
| 5 | `fs_hz` | u32 | 采样率（标称值；实测 47949 Hz） |
| 6 | `win` | u16 | 特征窗长（样本数），512 |
| 7 | `bands` | u8 | 分析频带数，2 |
| 8 | `caps` | u16 | 能力位图，当前 0 |

> 上位机靠 `major`/`minor` 判断能不能解析后续帧；不认识的版本会在状态栏黄字提示。

---

## T 帧 —— 遥测主帧（50 Hz）

```
T,1024,216446311,2780,1990,-900,-900,753,0,7,7,0
```

| # | 字段 | 类型 | 说明 |
|---|---|---|---|
| 1 | `seq` | u32 | 帧序号，用于算丢帧 |
| 2 | `t_us` | u64 | 时间戳 |
| 3 | `temp` | s16 | 温度，哨兵 −32768 |
| 4 | `hum` | u16 | 湿度，哨兵 65535 |
| 5 | `db_low` | s16 | 低频带能量，哨兵 −32768 |
| 6 | `db_high` | s16 | 高频带能量，哨兵 −32768 |
| 7 | `ber` | u16 | 频带能量比（千分比），哨兵 65535 |
| 8 | `state` | u8 | 0 正常 / 1 关注 / 2 事件中 |
| 9 | `lock` | u32 | 累计锁存次数（来自 PL） |
| 10 | `det` | u32 | 累计判定次数（来自 PS） |
| 11 | `supp` | u32 | 被抑制的次数（语音等） |

**丢帧计算**：`lost = (seq_now - seq_prev - 1)`，累加即可。

---

## E 帧 —— 事件快照

事件发生时立即发送，内容是触发瞬间的特征：

```
E,2048,84431200,-669,-410,997,813,27,2
```

| # | 字段 | 类型 | 说明 |
|---|---|---|---|
| 1 | `seq` | u32 | 序号 |
| 2 | `t_us` | u64 | 事件时间戳 |
| 3 | `db_low` | s16 | 低频能量 |
| 4 | `db_high` | s16 | 高频能量 |
| 5 | `ber` | u16 | 触发时的能量比 |
| 6 | `thr` | u16 | 触发时的阈值 |
| 7 | `lock` | u32 | 锁存计数 |
| 8 | `reason` | u8 | 0 未知 / 1 PL 锁存 / 2 PS 判决 |

---

## S 帧 —— 状态与错误

```
S,3072,90000000,0,0,0
```

| # | 字段 | 类型 | 说明 |
|---|---|---|---|
| 1 | `seq` | u32 | 序号 |
| 2 | `t_us` | u64 | 时间戳 |
| 3 | `flags` | u16 | 状态位，见下表 |
| 4 | `err_cnt` | u32 | 设备错误累计（如传感器读失败） |
| 5 | `ovf_cnt` | u32 | FIFO 溢出累计 |

### flags 位定义

| 位 | 掩码 | 含义 |
|---|---|---|
| 0 | `0x01` | 温度高于基线 3 ℃ |
| 1 | `0x02` | PL 已锁存事件 |
| 2 | `0x04` | PL 判定为超阈值 |
| 3 | `0x08` | 基线学习期内 |
| 4 | `0x10` | 检测到能量突增 |
| 5 | `0x20` | 当前处于一次事件中 |
| 6 | `0x40` | 语音类（能量包络有明显间隙） |

---

## X 帧 —— 诊断中间量（v1.1 新增，10 Hz）

这是本项目最有信息量的一帧：把判决过程的中间量全部暴露出来，界面上那个"多维判决"浮层就是靠它渲染的。

```
X,30720,221234500,0,0,753,753,0,786,753,30,0,0,8,0,27
```

| # | 字段 | 类型 | 说明 |
|---|---|---|---|
| 1 | `seq` | u32 | 序号 |
| 2 | `t_us` | u64 | 时间戳 |
| 3 | `level` | u8 | 判决级别 0–3 |
| 4 | `score` | u32 | 卡方分数（Q16 定点前的整数分） |
| 5 | `ber` | u16 | 当前能量比 |
| 6 | `ber_res` | u16 | 残余能量比（去掉噪声底后） |
| 7 | `kurt` | u8 | 峭度等级 0–15（当前未接入，恒 0） |
| 8 | `thr` | u16 | 当前生效阈值 |
| 9 | `mu_ber` | u16 | 基线均值 μ |
| 10 | `sd_ber` | u16 | 基线标准差 σ |
| 11 | `nf_low` | u32 | 低频噪声底 |
| 12 | `nf_high` | u32 | 高频噪声底 |
| 13 | `flags` | u16 | 状态位（同 S 帧） |
| 14 | `ev_pl` | u16 | PL 侧事件计数 |
| 15 | `ev_ps` | u32 | PS 侧事件计数 |

**兼容性**：旧版上位机不认识 `X`，会当作 `E_UNKNOWN_FRAME` 丢弃，不影响 `T` 帧正常工作。所以加这一帧不破坏既有部署。

## 解析参考实现

`host_software/lib/protocol.py` 是完整实现，232 行，只用标准库。关键约定：

- `parse_line()` **永不抛异常**，非法输入返回 `ok=False` + `err` 码
- 哨兵值统一映射为 `None`，上层不用关心具体数字
- 单位换算（0.01 ℃ → ℃、千分比 → 0–1）在解析层完成

测试见 `host_software/tests/test_protocol.py`（27 个用例）。
